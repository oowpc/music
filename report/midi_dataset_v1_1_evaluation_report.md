# MIDI 数据集 v1.1 曲风区分效果评估报告

## 1. 分析目的

本报告针对新增数据集 `midi_dataset_v1.1` 进行曲风相似性与分类效果评估，重点回答以下问题：

- v1.1 数据集相比 v1.0 是否具有更好的曲风区分度；
- Modified Hausdorff 距离在新数据集上的表现如何；
- KNN 分类能否有效判别曲风；
- 哪些曲风容易区分，哪些曲风仍然容易混淆；
- 标准 Hausdorff、Modified Hausdorff、离散 Fréchet、DTW 等方法在新数据上的效果差异。

## 2. 数据集概况

数据路径：

```text
data/midi_dataset_v1.1/data/raw
```

数据集包含 5 个曲风类别：

| 曲风 | 原始数量 |
|---|---:|

本次实验中，`rock/AchillesLastStand.mid` 在解析时耗时异常，因此暂时跳过。实际参与评估的样本数为 124 首：

| 曲风 | 实际参与评估数量 |

## 3. 预处理流程

本次评估采用与前期实验一致的主流程：

1. 使用 `music21` 解析 MIDI；
2. 使用 `highest` 模式提取主旋律，即同一时间点保留最高音；
3. 对旋律曲线做 Min-Max 归一化；
4. 将每首曲线统一重采样为 64 个旋律点；
5. 使用 Modified Hausdorff 距离构建距离矩阵；
6. 基于距离矩阵计算曲风内距离、曲风间距离和 KNN 分类结果。

重采样的原因是 v1.1 中部分 MIDI 文件较长，若直接使用完整音符序列计算 Fréchet 或 DTW，计算量会显著增加。统一重采样后可以保证不同方法在同一分辨率下比较。

## 4. 曲风相似性分析

### 4.1 整体距离统计

使用 Modified Hausdorff 距离得到：

| 指标 | 数值 |
|---|---:|
| 曲风内平均距离 | 0.091023 |
| 曲风间平均距离 | 0.214359 |
| 区分比 | 2.355 |

其中：

```text
区分比 = 曲风间平均距离 / 曲风内平均距离
```

区分比越大，说明同一曲风内部越集中，不同曲风之间越分离。

与 v1.0 清洗后的区分比约 `1.335` 相比，v1.1 的区分比达到 `2.355`，说明新数据集的曲风区分度明显提升。

### 4.2 曲风距离矩阵

| 曲风 | classical | folk | jazz | pop | rock |
|---|---:|---:|---:|---:|---:|
| classical | 0.101070 | 0.285336 | 0.104151 | 0.232411 | 0.263501 |
| folk | 0.285336 | 0.025897 | 0.317359 | 0.143726 | 0.172751 |
| jazz | 0.104151 | 0.317359 | 0.097025 | 0.229845 | 0.269921 |
| pop | 0.232411 | 0.143726 | 0.229845 | 0.081978 | 0.123474 |
| rock | 0.263501 | 0.172751 | 0.269921 | 0.123474 | 0.154199 |

### 4.3 距离矩阵解读

从矩阵可以看出：

- `folk` 内部距离最低，仅为 `0.025897`，说明 folk 样本内部非常集中；
- `pop` 内部距离为 `0.081978`，也比较稳定；
- `classical` 与 `jazz` 的曲风间距离为 `0.104151`，接近两者各自的内部距离，因此这两类容易混淆；
- `pop` 与 `rock` 的曲风间距离为 `0.123474`，低于 rock 内部距离 `0.154199`，说明 rock 样本存在明显向 pop 靠近的情况；
- `rock` 内部距离最大，为 `0.154199`，说明 rock 类内部差异较大。

## 5. KNN 分类实验

### 5.1 实验设置

使用 leave-one-out KNN 分类方法：

1. 每次取一首歌曲作为测试样本；
2. 其余歌曲作为训练样本；
3. 根据距离矩阵寻找最近的 K 首歌曲；
4. 使用多数投票预测测试样本曲风；
5. 统计 Accuracy、Macro-F1 等指标。

### 5.2 KNN 结果

| K | Accuracy | Macro-F1 |
|---:|---:|---:|
| 1 | 0.7823 | 0.7686 |
| 3 | 0.7500 | 0.7328 |
| 5 | 0.7984 | 0.7762 |
| 7 | 0.7661 | 0.7452 |
| 9 | 0.7258 | 0.6794 |

最佳结果为：

| 指标 | 数值 |
|---|---:|
| 最佳 K | 5 |
| Accuracy | 0.7984 |
| Macro-F1 | 0.7762 |

相比 v1.0 清洗后 KNN 最佳准确率约 `60.71%`，v1.1 提升到约 `79.84%`，说明新数据集更适合用于曲风判别实验。

## 6. 混淆矩阵分析

K=5 时的混淆矩阵如下：

| true \ pred | classical | folk | jazz | pop | rock |
|---|---:|---:|---:|---:|---:|
| classical | 22 | 0 | 3 | 0 | 0 |
| folk | 0 | 25 | 0 | 0 | 0 |
| jazz | 6 | 0 | 19 | 0 | 0 |
| pop | 0 | 0 | 0 | 25 | 0 |
| rock | 3 | 1 | 0 | 12 | 8 |

### 6.1 易识别曲风

`folk` 和 `pop` 的识别效果最好：

- folk：25 首全部预测正确；
- pop：25 首全部预测正确。

这说明这两类在当前旋律几何特征下具有较强的可分性。

### 6.2 容易混淆曲风

`classical` 和 `jazz` 存在明显混淆：

- classical 中有 3 首被预测为 jazz；
- jazz 中有 6 首被预测为 classical。

这与距离矩阵一致，因为 classical 与 jazz 的曲风间距离仅为 `0.104151`，非常接近它们的曲风内距离。

`rock` 的分类效果最弱：

- 24 首 rock 中，仅 8 首被正确预测为 rock；
- 12 首被预测为 pop；
- 3 首被预测为 classical；
- 1 首被预测为 folk。

这说明 rock 类内部差异较大，并且部分样本在旋律几何形状上更接近 pop。

## 8. 四种距离方法对比

为了比较不同距离方法的影响，从每个曲风中抽样 10 首，共 50 首，统一重采样为 64 个旋律点，比较四种方法：

- 标准 Hausdorff；
- Modified Hausdorff；
- 离散 Fréchet；
- DTW。

结果如下：

| 方法 | 曲风内均值 | 曲风间均值 | 区分比 | KNN Accuracy | Macro-F1 |
|---|---:|---:|---:|---:|---:|
| 标准 Hausdorff | 0.274173 | 0.422655 | 1.542 | 0.7200 | 0.7056 |
| Modified Hausdorff | 0.094716 | 0.211536 | 2.233 | 0.8200 | 0.7823 |
| 离散 Fréchet | 0.359256 | 0.473430 | 1.318 | 0.5800 | 0.5564 |
| DTW | 0.130392 | 0.252133 | 1.934 | 0.7200 | 0.6905 |

### 8.1 方法对比结论

Modified Hausdorff 表现最好：

- 区分比最高：`2.233`；
- KNN Accuracy 最高：`0.8200`；
- Macro-F1 最高：`0.7823`。

DTW 表现次之，区分比为 `1.934`，说明它对旋律走势相似但节奏不同的情况有一定优势。

标准 Hausdorff 有一定区分能力，但不如 Modified Hausdorff 稳定。

离散 Fréchet 在本次抽样中效果最弱，可能是因为它对顺序差异较敏感，而曲风分类更需要整体形状统计而非严格顺序匹配。

## 10. 总体结论

v1.1 数据集质量明显优于 v1.0，主要体现在：

- 曲风间距离明显大于曲风内距离；
- 区分比从 v1.0 清洗后的约 `1.335` 提升到 v1.1 的 `2.355`；
- KNN 最佳准确率从约 `60.71%` 提升到 `79.84%`；
- 新增的 folk 类表现非常稳定，25 首全部识别正确；
- pop 类也非常稳定，25 首全部识别正确。

当前主要问题是：

- classical 与 jazz 仍然接近，存在互相混淆；
- rock 类内部差异较大，且大量样本被判为 pop；
- `rock/AchillesLastStand.mid` 解析耗时异常，需要单独处理或优化解析流程。

综合来看，v1.1 更适合作为后续曲风分类、距离方法比较和可视化分析的主数据集。

## 11. 后续建议

后续可以继续做以下优化：

- 对 `rock` 类进行质量检查，重点分析被预测为 pop 的样本；
- 对 `classical` 与 `jazz` 增加节奏、和声、音程分布等特征，减少混淆；
- 对超大或解析缓慢 MIDI 增加超时机制；
- 在 UI 中增加批量数据集评估入口；
- 为结果文件自动生成报告；
- 在方法对比中支持完整数据集的后台异步计算。
