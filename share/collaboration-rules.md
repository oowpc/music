# 项目协作规范

为保持仓库整洁、避免冲突、确保可复现性，所有合作者必须严格遵守以下规则。

---

## 一、顶级目录与文件要求

1. **必须包含以下顶级文件**
   - `.gitignore`：按第十节要求配置。
   - `README.md`：包含项目简介、环境配置、运行步骤、归一化说明等。
   - `requirements.txt`（或 `environment.yml`）：固定所有依赖版本。待具体设计完成后放置于根目录。
   - `LICENSE`：保持现有许可证。

2. **必须包含以下六个一级目录**（大小写严格一致）
   - `docs/`
   - `ai_conversations/`
   - `share/`
   - `src/`
   - `tests/`
   - `report/`

## 二、`docs/` 目录规范

3. **用途**：存放正式的、稳定的项目计划、设计文档、过程记录（如本规范文档）。

## 三、`ai_conversations/` 目录规范

4. **用途**：备份与 AI 助手的完整对话记录（JSON 格式），此内容相对最不重要。

## 四、`share/` 目录规范

5. **用途**：存放不正式的、需要临时写入以便后续引用或留档的文档（如跨上下文总结、会议速记、草稿、参考链接集）。
6. **允许任何文本或 Markdown 文件**，但禁止提交二进制大文件（如图片、压缩包）。
7. **清理规则**：每个合作者可自由编辑此目录，但版本合并前需自行解决冲突。

## 五、`data/` 目录规范

8. **该目录必须被 `.gitignore` 完全忽略**，禁止任何数据文件提交至 Git 仓库（包括 `raw/` 和 `processed/` 子目录）。`data/` 为本地目录，不会上传至仓库。

## 六、`src/` 目录规范

9. 所有 Python 源代码必须放在 `src/` 下，按功能模块拆分文件。
10. 辅助函数统一放在 `src/utils/` 下，例如 `src/utils/plotting.py`, `src/utils/normalization.py`。
11. 每个函数必须包含 docstring，说明输入输出形状与含义。
12. 禁止在 `src/` 目录下存放数据、结果、配置密文或未使用的旧代码。

## 七、`tests/` 目录规范

13. 所有单元测试文件放在 `tests/` 下，文件名以 `test_` 开头。
14. AI 代理临时运行代码产生的临时拍摄文件也放在此文件夹中（在仓库同步前清除这部分临时文件）。

## 八、`report/` 目录规范

15. 该目录用于存放最终的毕设报告（如 `main.tex`、`final_report.pdf`）及相关附件、图片。
16. 合作者不得在 `report/` 内创建子目录，除非经所有人同意。
17. 提交报告前，该目录应仅包含报告源文件及必要附件。

## 九、`results/` 目录（可选）

18. 如果需要在仓库中保存少量总结性结果（如距离矩阵热图、统计图表、分类准确率表格），可创建 `results/` 目录。
19. `results/` 只接受**轻量级总结文件**（例如 `.csv` 结果汇总表、`.png` 图像、`.txt` 日志摘要）。
20. **大量处理后的数据（如超过 5 MB 的数组、所有音符序列的缓存）必须放在 `data/` 子文件夹中，而不是 `results/`**。

## 十、`.gitignore` 规范

21. `.gitignore` 必须包含以下条目：

```gitignore
# Python
__pycache__/
*.py[cod]
*.so
.Python
venv/
.venv/
env/
ENV/

# 数据目录（完全忽略）
data/

# 临时文件
*.log
*.tmp
*.aux
*.out

# IDE
.vscode/
.idea/
*.swp
.DS_Store

# Jupyter
.ipynb_checkpoints/

# 配置文件（本地）
*.local.cfg
.env
```
